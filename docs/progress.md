- 各ページは約300dpiの画像1枚。元画像を劣化させずに抽出できる。
- 表紙は『インフィニティ・リミテッド 上』。PDFページ12は印刷ページ10、PDFページ35は印刷ページ33。
- 本文は縦書きで、ルビとノンブルがある。PDFページ100のように本文が少ないページもある。
- NDLOCR-Lite 1.3.0 (`e57f7c6bd9cfb3de5f12f008e71ad2122bd44bfd`) と PaddleOCR 3.7.0 / PP-OCRv6 を、それぞれ Python 3.11 の独立した仮想環境に導入した。
- PDFページ12で両OCRの結果を取得。NDLOCR-Liteの認識処理は約1秒。PaddleOCRの初回実行はモデル取得込みで約27秒。
- PaddleOCRの結果は検出順に並び、PDFページ12のノンブルも本文と同じ一覧に入る。NDLOCR-Liteの結果にはノンブルが入っていない。座標と領域分類を使う必要がある。
- NDLOCR-Liteはページ12の「ノック」を認識。PaddleOCRは同じ箇所を「ノク」と出した。単独OCRの確信度だけでは採否を決められない。
- ページ12はNDLOCR-Liteの18列・647文字に対し、PaddleOCRとの編集距離43。ページ35は18列・698文字に対し同43。これは正解率でなく不一致量。
- ページ12のルビ「きぜん」は、NDLOCR-LiteのXMLが領域を「ルビ」として検出し、PaddleOCRが文字を認識した。NDLOCR-Liteの本文JSONにはルビ文字が入らない。両者の座標を合わせて復元できる可能性がある。
- NDLOCR-Liteの実装を確認。文字認識へ渡す対象はXMLの `LINE` 要素で、検出済みのルビは `BLOCK TYPE="ルビ"` として残るため認識対象外になる。通常版NDLOCRには独立した `ruby_prediction` 工程がある。今回の欠落はLite版の処理経路によるもので、認識モデル自体のルビ精度は未評価。
- PaddleOCRはこの2ページで句読点・括弧の脱落が多い。NDLOCR-Liteも数字・記号で誤認識が見える。モデルの確信度だけで自動採用しない。
- `bin/compare-ocr.rb` で縦列を座標で対応付け、文字単位の差分位置を表示できるようにした。NDLOCR-LiteのXMLがあれば、未対応のPaddleOCR領域をルビ・ノンブルに分類する。ページ12の「きぜん」「10」、ページ35の「33」を正しく分類した。
- `bin/build-review.rb` で原本画像、両OCRの列ごとの比較、ルビ・ノンブルを1枚のローカルHTMLにまとめる。差分の強調と原本位置の選択・拡大に対応。

## 方針

1. NDLOCRとPaddleOCRの領域・行を座標で対応付け、文字単位の差分を保存する。
2. 本文・ルビ・柱・ノンブル・図版を分ける。ルビ内の大きい仮名と小書き仮名が割れたときは、大きい仮名に補助票を与える。
3. VLMは不一致部分の原画像を確認する。自動校正は対象文の文字数を変えず、候補外の作文を採用しない。欠落・挿入は人の確認に回す。
4. Jevなどの decision model は候補選択または評価役として、正解を付けたページで有効性を測る。
5. カラー図版は色を維持する。白黒線画の紙色除去は白背景と透過の両方を試し、写真や網点画には一律適用しない。
6. 確認済みの本文から、縦書き・横書きのリフロー可能なEPUBを生成する。
